Introduction to conquestr

Dan Cloney

2026-10-26

conquestr has three main functions:

  • ConQuestCall: calls ‘ACER ConQuest’ in a terminal and runs syntax
  • ConQuestSys: reads and returns ‘ACER ConQuest’ system files as an R object. For example, this provides access to parameter estimates, abilities, and raw data.
  • ConQuestRout (and plotRout): reads ‘ACER ConQuest’ plot objects (see the command plot) and creates plots in R via generic functions and dispatch.

These functions allows users to include ‘ACER ConQuest’ within their R workflow. This is particularly useful for users of the Mac OS X version (and Windows console) version of ‘ACER ConQuest’ which does not support ploting.

This vignette demonstrates how to use the package built-in demonstration files to:

  • Call ‘ACER ConQuest’ and run a syntax file
  • Read in a system file and access data objects

Call ConQuest and run a syntax file

First, ensure you have the most current version of ConQuest. Version > 5.17.4 is required. If you are unsure, check ConQuest on the ACER Shop. You will also need to install the conquestr library:

install.packages("conquestr")
library("conquestr")

You must pass the ConQuestCall function at least two pieces of information: the install location of ConQuest and a valid syntax file. conquestr has included syntax files that can be used to run a model and test other package functions. A default syntax file will be called is you do not explicitly provide one. conquestr will search for a valid installation of ‘ACER ConQuest’ unless the executable is explicitly declared. The search locations are (in order):

  • The default install location (Windows:%ProgramFiles%\ACER ConQuest\ConQuestConsole.exe and Mac OS X: /Applications/ConQuest/ConQuest).
  • The Program Files folder on Windows, and the Application folder on Mac OS X
  • The current user’s Desktop
# if you don't provide a syntax file, using the argumenmt `cqc=`, then the in-built demo syntax file will be run. 
ConQuestCall()

When you use ConQuestCall to call ‘ACER ConQuest’ and run a syntax file, some options are set by default. The same options can be set within ‘ACER ConQuest’ by using the set command (set progress = yes, exit_on_error = yes, storecommands = yes, warnings = no; which is syntactically the same as using the helper function set conquestr = true;). WARNING - this will make it easy to overwrite output as you will not be prompted or warned. To turn off these settings your syntax file must explicitly change these using the set command. For more information see the set command.

When calling ‘ACER ConQuest’ from R, the ConQuest working directory will default to the current R working directory. This makes it easy to write portable syntax using relative paths. If you need ‘ACER ConQuest’ to use a different working directory, set it in your syntax file.

Read in a ConQuest system file

The above example created a system file. Alternatively, there is an inbuilt example of a system file.

conquestr can read in a system file, using the ConQuestSys function. This function returns a list that includes the response data, parameter estimates, and other data objects created by ‘ACER ConQuest’. These lists can be optionally coerced into R data frames.

# if no argument is provided to ConQuestSys, the example system file is read in by default.
myCqs <- ConQuestSys()
#> no system file provided, loading the example system file instead
#> System file is compressed. Decompressing ...
#> complete

You can see the data objects available within the object (e.g., str(myCqs)), and some useful objects will be:

  • gResponseData - The raw response data including information about the raw and key response to each item.
  • gYData - The regression data included in the estimation.
  • gAllCaseEstimates - the latent ability estimates (e.g., PVs, WLEs).
  • The option matrixout is available for several commands and will ensure data objects are saved to the system file - these can be found in gMatrixList. For example:
    • The command matrixsampler and the option matrixout creates the objects matrixSampler_fit, matrixSampler_raw, matrix_userfit (the simulated data) in gMatrixList.
    • The command itanal, and the option matrixout creates the objects *_counts, *_itemstats, *_ptbis, *_abilitymeansd (where “*” is a user defined prefix declared in the option matrixout) in gMatrixList .
    • The command estimate and the option matrixout… for more information see the manual

Users can search the names of objects in the system file using the helper function searchConQuestSys:

# search for objects named history in myCqs
searchConQuestSys("history", myCqs)
#> [1] "gHistoryWeights" "gOldHistory"     "gBestHistory"    "gHistory"       
#> [5] "gCommandHistory"

Population statistics from plausible values

Large-scale assessments such as PISA report student achievement as a set of plausible values (PVs) and provide replicate weights for estimating sampling error. conquestr provides a family of functions that compute a statistic for each PV under the full-sample weight and under every replicate weight, then combine the results using Rubin’s rules:

  • pvStat() - the core function (any supported statistic, optionally by group)
  • pvMean(), pvSd(), pvVar(), pvMedian(), pvQuantile(), pvIqr() and pvDescribe()
  • pvDiff() - differences between groups (e.g., girls minus boys)
  • pvCor() - correlations between PVs and background variables
  • pvRegression() - weighted linear regression of PVs on background variables

Supported replication methods are "BRR", "Fay" (Fay’s variant of BRR, as used in PISA), "JK1" (delete-one jackknife) and "JK2" (paired jackknife, as used in TIMSS and PIRLS).

Simulate a PISA-style dataset

The example below simulates 64 schools in 32 variance strata (pairs of schools), 20 students per school, 10 PVs and Fay replicate weights (k = 0.5) built from a Hadamard matrix. PISA uses 80 replicates; 32 are used here to keep the example small.

set.seed(5309)
nStrata <- 32
nSchools <- nStrata * 2
nPerSchool <- 20
nPVs <- 10

# Sylvester construction of a 32 x 32 Hadamard matrix
hadamard <- matrix(1)
while (nrow(hadamard) < nStrata) hadamard <- rbind(cbind(hadamard, hadamard), cbind(hadamard, -hadamard))

school <- rep(seq_len(nSchools), each = nPerSchool)
stratum <- (school + 1) %/% 2
unit <- ifelse(school %% 2 == 1, 1, -1) # first or second school in the pair
n <- length(school)

pisaSim <- data.frame(
  school = school,
  sex = factor(sample(c("boy", "girl"), n, replace = TRUE)),
  escs = rnorm(nSchools, 0, 0.5)[school] + rnorm(n, 0, 0.8),
  W_FSTUWT = runif(n, 5, 50)
)
schoolEffect <- rnorm(nSchools, 0, 40)[school]
trueTheta <- 480 + 30 * pisaSim$escs + 12 * (pisaSim$sex == "girl") + schoolEffect + rnorm(n, 0, 70)
for (p in seq_len(nPVs)) {
  pisaSim[[paste0("PV", p, "READ")]] <- trueTheta + rnorm(n, 0, 25) # imputation noise
}

# Fay replicate weights: one school in each pair gets 1.5, the other 0.5
fayK <- 0.5
for (r in seq_len(nStrata)) {
  factorR <- ifelse(hadamard[stratum, r] * unit > 0, 2 - fayK, fayK)
  pisaSim[[paste0("W_FSTR", r)]] <- pisaSim$W_FSTUWT * factorR
}

pvs <- paste0("PV", seq_len(nPVs), "READ")
repWts <- paste0("W_FSTR", seq_len(nStrata))

imputationVar is B before Rubin’s correction, so the columns do not simply add up to se^2. The reported estimate is the average of only M PV estimates, and that average has its own simulation error with variance B / M. Rubin’s rules add it, so the total error variance is

\[\mathrm{SE}^2 = U + \left(1 + \tfrac{1}{M}\right) B.\]

With 10 PVs this adds 10% to B. To recover se from the columns:

desc <- pvDescribe(pisaSim, pvs, weight = "W_FSTUWT", repWeights = repWts,
                   repMethod = "Fay", fayK = fayK)
all.equal(desc$se, sqrt(desc$samplingVar + (1 + 1 / desc$nPVs) * desc$imputationVar))
#> [1] TRUE

The same holds for pvDiff(), pvCor() (on the z scale when combine = "fisherZ") and pvRegression(). See ?pvStat for details.

Group differences

pvDiff() computes the difference within each PV and replicate, so the standard error accounts for the covariance between groups that is induced by the sampling design.

pvDiff(pisaSim, pvs, by = "sex", pairs = list(c("girl", "boy")),
       weight = "W_FSTUWT", repWeights = repWts, repMethod = "Fay", fayK = fayK)
#>     contrast stat estimate       se samplingVar imputationVar        t
#> 1 girl - boy mean 18.09364 5.634755    29.94789      1.638702 3.211079

Correlations

pvCor() combines correlations on the raw r scale by default, or on the Fisher-z scale with combine = "fisherZ". The Fisher-z option gives confidence intervals that stay within [-1, 1].

pvCor(pisaSim, pvs, "escs", weight = "W_FSTUWT", repWeights = repWts,
      repMethod = "Fay", fayK = fayK, combine = "fisherZ")
#>   variable  estimate         se samplingVar imputationVar   ciLower   ciUpper
#> 1     escs 0.2801781 0.04637565 0.002369299   0.000148575 0.1870107 0.3683502
#>   zEstimate        zSe combine nPVs nReps    n
#> 1 0.2878754 0.05032625 fisherZ   10    32 1280

Correlation and covariance matrices

pvCorMatrix() and pvCovMatrix() estimate the matrix for several measures at once. Each measure is either latent (its PV columns, in draw order) or manifest (a single observed column). Latent measures are paired by draw (PV1 with PV1, PV2 with PV2, …), which is appropriate when their PVs were drawn jointly from one multidimensional model. A manifest variable is the same in every draw, so its column is reused for each PV.

To illustrate, add a second latent domain (mathematics) drawn jointly with reading, and an observed variable (age in months):

trueMath <- 0.7 * (trueTheta - 480) + 470 + rnorm(n, 0, 60)
for (p in seq_len(nPVs)) {
  shared <- rnorm(n) # joint draw: reading and maths PV p share an error component
  pisaSim[[paste0("PV", p, "MATH")]] <- trueMath + 20 * shared + rnorm(n, 0, 15)
}
pisaSim$age <- round(rnorm(n, 189, 3.5))

measures <- list(
  read = paste0("PV", seq_len(nPVs), "READ"),
  math = paste0("PV", seq_len(nPVs), "MATH"),
  escs = "escs",
  age = "age"
)

The matrix format returns symmetric matrices of estimates, standard errors and confidence limits:

corMat <- pvCorMatrix(pisaSim, measures, weight = "W_FSTUWT", repWeights = repWts,
                      repMethod = "Fay", fayK = fayK, format = "matrix")
round(corMat$estimate, 3)
#>        read   math   escs    age
#> read  1.000  0.653  0.280 -0.029

#> escs  0.280  0.165  1.000 -0.036
#> age  -0.029 -0.012 -0.036  1.000
round(corMat$se, 3)
#>       read  math  escs   age

The long format has one row per pair. Pairs of two manifest variables are ordinary weighted correlations, so imputationVar is 0 and nPVs is 1:

pvCorMatrix(pisaSim, measures, weight = "W_FSTUWT", repWeights = repWts,
            repMethod = "Fay", fayK = fayK)[, c("dim1", "dim2", "estimate", "se",

Two cautions apply when mixing latent and manifest measures:

  • A correlation between PVs and an observed variable is unbiased only if that variable (or a good proxy) was in the population (conditioning) model used to draw the PVs; otherwise it is biased towards zero. Here age was not used to generate the PVs and is unrelated to proficiency, so its correlations are near zero by construction. Check the study’s scaling documentation before interpreting such correlations.
  • With combine = "fisherZ", each element is back-transformed separately, so the matrix is not guaranteed to be positive semi-definite; a warning is given if it is not. The default, combine = "raw", always gives a valid matrix.
